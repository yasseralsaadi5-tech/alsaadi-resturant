## لم يتم اختباره فعلياً (ولا ادّعاء بخلاف ذلك)
- **لم يُشغَّل** `npm install` أو `npm run build` — بيئة التنفيذ الحالية بلا
  اتصال إنترنت فعلي. يجب على المستخدم تشغيلهما محلياً للتحقق من نجاح البناء.
- **لم يُختبر** الموقع فعلياً على متصفح حقيقي أو أي من أحجام الشاشات المذكورة
  في المواصفة (320px إلى 3840px) — التصميم مبني mobile-first بـ Tailwind
  بشكل نظري، لكن لا يوجد دليل تشغيلي فعلي.
- **لم يُختبر** تدفق تسجيل الدخول/الخروج الفعلي في متصفح حقيقي.
- **لم يُختبر** رفع صورة فعلي عبر واجهة لوحة التحكم (الكود مكتوب ويعتمد على
  Supabase Storage API الموثقة رسمياً، لكن بلا تشغيل فعلي هنا).

## إصلاحات
- search_path غير ثابت في دالة `is_admin()` → تم تثبيته بـ
  `set search_path = public` وتأكيد الإصلاح عبر get_advisors.
- **خطأ حقيقي أبلغ عنه المستخدم**: لوحة التحكم لا تظهر إطلاقاً. السبب:
  `src/app/admin/layout.tsx` كان يُطبَّق على كل المسارات تحت `/admin` **بما
  فيها `/admin/login` نفسها**، ويحتوي على `if (!user) redirect("/admin/login")`
  بلا شرط استثناء. أي زائر غير مسجل دخول يفتح `/admin/login` كان يُعاد توجيهه
  إلى... `/admin/login` نفسها، مما يُنتج حلقة إعادة توجيه لا نهائية (تظهر في
  المتصفح كـ"too many redirects" أو صفحة لا تُحمَّل إطلاقاً). الـ middleware
  كان يستثني `/admin/login` بشكل صحيح، لكن الـ layout لم يكن يعرف بذلك.
  **الإصلاح**: نقل الصفحات المحمية (orders, menu, categories, الصفحة
  الرئيسية للوحة) إلى مجموعة مسارات Next.js باسم `(protected)`، بينما بقيت
  `login/page.tsx` خارجها تماماً وغير مغلَّفة بذلك الـ layout. مجموعات
  المسارات في Next.js لا تظهر في الرابط، لذلك كل الروابط الداخلية
  (`/admin/orders`, `/admin/login`...) بقيت كما هي دون أي تعديل.
  **التحقق**: تم تتبع مسار الطلب منطقياً عبر الكود (middleware → تحليل
  المسار → أي layout يُطبَّق) للتأكد من كسر الحلقة في الحالات الثلاث
  (زائر على /admin/login، زائر على /admin/orders، أدمن مسجل دخول). **لم يتم
  تشغيل هذا فعلياً في متصفح حقيقي** لعدم توفر بيئة تشغيل هنا (لا node_modules،
  لا إنترنت) — يُرجى تشغيل `npm run dev` والتأكد أن `/admin/login` يفتح الآن
  بلا حلقة، وإخباري إن ظهر أي خطأ آخر.

- **خطأ Hydration حقيقي أبلغ عنه المستخدم فعلياً بعد تشغيل `npm run dev`**:
  متاجر Zustand الثلاثة (cart-store, theme-store, last-order-store) تستخدم
  `persist` مع localStorage. في Next.js، هذه المتاجر تُعاد قراءتها من
  localStorage بشكل متزامن عند إنشائها على المتصفح — أي قبل أول مقارنة
  hydration مع HTML القادم من الخادم (الذي يحتوي دائماً القيم الافتراضية
  لأن الخادم لا يملك localStorage). هذا يسبب اختلافاً حقيقياً بين HTML
  الخادم والعميل (مثال: شارة عدد أصناف السلة تظهر فجأة).
  **الإصلاح**: أضفنا `skipHydration: true` للمتاجر الثلاثة، ثم أعدنا
  الترطيب (rehydrate) يدوياً داخل `useEffect` في `ThemeProvider` بعد
  التركيب (mount) — فيصبح أول عرض على العميل مطابقاً تماماً للخادم، ثم
  تُحدَّث القيم بعد ذلك عبر تحديث React عادي لا يُقارَن مع HTML الخادم.
  لم يُعَد اختبار هذا الإصلاح فعلياً في متصفح حقيقي (بيئة الإنشاء بلا واجهة
  متصفح)، لكنه النمط الموثق رسمياً من مكتبة Zustand لهذه المشكلة تحديداً.

- **تحذير Hydration ثالث أبلغ عنه المستخدم بصورة فعلية من متصفحه**: الفرق
  الوحيد في شجرة DOM كان خاصية `bis_skin_checked="1"` مضافة على عنصر `<div>`
  لم تُنشئها شيفرتنا إطلاقاً (تحقق: بحث شامل في src لم يجد أي أثر لها).
  هذه الخاصية توقيع معروف لإضافات متصفح (مانع إعلانات، شريط أدوات حماية،
  أو إضافة تسوق) تُدخل تعديلات على الصفحة قبل اكتمال React من الترطيب —
  ورسالة الخطأ نفسها تذكر هذا السيناريو صراحة. **الإصلاح**: أضفنا
  `suppressHydrationWarning` على وسم `<body>` فقط في `layout.tsx` — الحل
  الموثق رسمياً في Next.js لهذه الحالة تحديداً؛ يتجاهل فروقات الخصائص على
  ذلك العنصر فقط دون إخفاء أي تعارضات حقيقية أخرى في الشجرة. لم يُعَد
  اختباره في متصفح حقيقي هنا لعدم توفر بيئة تشغيل.
